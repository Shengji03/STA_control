# 项目结构与重构边界

## 运行代码与实验代码

`src` 保存能够复用的运行组件；`experiments` 保存预设任务、训练和评价。
旧 `wrist` 包及其兼容入口已经删除。网页服务复用 `TaskRunner`，不导入实验脚本。
实验模块可以依赖运行组件，运行组件不应依赖实验模块。

任务运行路径：

```text
cli / web_backend
  -> llm_planner（自然语言任务）或直接读取 plan
  -> pipeline.PlanExecutor
  -> pipeline.TaskRunner
  -> skills + motion_planning
  -> controller
  -> MuJoCo
```

规划器使用 `perception` 生成的结构化场景状态，反馈机制负责任务、
可达性、逆运动学与目标姿态接触检查。当前碰撞反馈没有完整扫描运动轨迹。

## 配置

- `config/paths.py`：项目资源和输出位置，禁止通过进程工作目录猜测默认路径。
- `config/robot.py`：当前主流程的自由度、初始关节角、双臂偏移、工作半径和导航参数。
- `config/llm.py`：命令行和网页共用的模型、服务地址、密钥优先级。
- `llm_planner/factory.py`：根据设置创建实际规划器。

配置模块只描述设置，导入时不会启动 MuJoCo、服务或 LLM 客户端。
已有实验中的双臂偏移值与主流程不同，本次迁移保留其原有数值，
应在独立的场景校准工作中与 XML 模型核对。
提示词还包含场景规则和坐标示例，后续可根据场景注册表逐步生成。

## 执行职责

- `pipeline/arm_state.py`：单臂运行状态。
- `pipeline/navigation.py`：先平移、后原地转向的导航时间曲线，不依赖 MuJoCo。
- `pipeline/plan_executor.py`：将 JSON 计划转换为阶段和技能。
- `pipeline/task_runner.py`：协调导航、双臂执行、技能切换、控制和仿真步进。
- `skills/arm_controller.py`：两个预设管道实验复用的单臂 STA 控制器。
- `visualization/trajectories.py`：TCP 轨迹绘制及图片输出。
- `experiments/metrics.py`、`reporting.py`：评价指标与对比展示。
- `motion_planning/joint_trajectory.py`：当前技能使用的三次关节轨迹。
- `motion_planning/rrt`：遮光实验使用的基础 RRT、节点、参数与机器人碰撞检查。
- `geometry`：机械臂胶囊体、遮光板长方体及 GJK 所需的几何基础。

关节轨迹直接计算三次时间规律，不再通过通用参数、策略和工厂层转发。
GJK 根据单纯形点数直接构建几何对象，不再依赖注册池。
包入口改为显式导出当前使用的对象，移除了通配导入。

主流程的速度误差计算和实验控制器的期望速度计算目前仍有差异。
本次共享控制器保持原实验输出；不借结构重构改变控制律或实验参数。
两个管道实验保留各自的任务阶段编排，避免将不同协作过程强行统一。

## 删除范围与保留依据

本次清理删除了 95 个旧 Python 源文件和两个旧示例场景。
其中仍在使用的 RRT 文件先迁移到新位置，其余旧轨迹目录再整体清空源码。
旧 ASGI 自动初始化入口已删除，网页通过 `run_enterprise_web.py` 或
`python -m src.cli.web` 启动。

`run_dialog.py` 和 `run_enterprise_web.py` 是当前文档指定的两个启动入口，
继续保留；它们调用 `src.cli`，没有重复的任务实现。
独立实验、DDPG、STA、导纳、机器人模型和实际使用的碰撞检查继续保留。
第三方模型资源及许可证也保留。

删减前记录了 81 个关节轨迹采样点、18 个碰撞配置和固定随机种子的
RRT 路径。删减后对照全部通过；关键样本和路径已加入回归测试。
模型权重统一使用 `outputs/models`，不再读取旧 `wrist` 路径。

## 后续结构整理项

| 区域 | 目前情况 | 后续处理依据 |
|---|---|---|
| 技能、控制参数 | STA 默认值和导纳配置仍放在各自模块 | 统一参数格式时同步验证各技能控制效果 |
| PlanExecutor 和 TaskRunner | 计划结构仍以字典表示，遮光协作由规则触发 | 定义明确的阶段、依赖和协作模式，再替换隐式判断 |
| Web 仿真状态 | 历史、日志保存在内存，部分任务参数尚未连接执行 | 先明确接口语义，再实现配置和数据保存 |
| 实验循环 | 各任务仍有自己的仿真循环 | 建立覆盖完整任务的基线后再合并生命周期 |

HTN、次模优化和 CARLA 属于新的研究功能，不计入本轮结构重构。
现有测试通过能够证明已覆盖行为得到保留，不能替代完整装配、遮光或
DDPG 多轮训练的实验验证。
